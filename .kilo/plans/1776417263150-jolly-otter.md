# Plan: Auto-extract Weight/Volume from Product Names

## Problem
The customer has been entering products with weight/volume in the product name (e.g. "Horse & Pony Cubes 20kg", "Fly Repellent Spray 500ml") but not filling in the `weight_kg` / `volume_litres` database fields. These fields are used for shelf label unit pricing (price per kg, per litre, etc.).

## Approach
1. Add a parser function that extracts weight/volume from product names
2. Hook it into all product creation/edit paths so future products auto-populate
3. Run a backfill on app startup for existing products

## Files to Modify

### 1. `farmprices/helpers.py` — Add `parse_weight_volume()` function

Add a new function that uses regex to extract weight/volume from a product name string:

```python
def parse_weight_volume(name: str) -> tuple[float | None, float | None]:
    """Extract weight_kg and volume_litres from a product name string.
    Returns (weight_kg, volume_litres) — either or both may be None."""
```

**Regex patterns** (case-insensitive):
| Pattern | Example matches | Stored as |
|---------|----------------|-----------|
| `(\d+(?:\.\d+)?)\s*kg\b` | `20kg`, `25kg`, `0.5kg` | `weight_kg` directly |
| `(\d+(?:\.\d+)?)\s*g\b` (not preceded by `k`) | `200g`, `7.74g`, `500g` | `weight_kg` = value / 1000 |
| `(\d+(?:\.\d+)?)\s*ml\b` | `500ml`, `100ml` | `volume_litres` = value / 1000 |
| `(\d+(?:\.\d+)?)\s*l\b` (not preceded by `m`) | `1L`, `1000L`, `12L` | `volume_litres` directly |

**Edge cases handled:**
- `25kg` won't also match the `g` pattern (negative lookbehind for `k`)
- `500ml` won't also match the `l` pattern (negative lookbehind for `m`)
- Dimensions like `50m`, `400m`, `2x1m` are ignored (no `m` pattern)
- Returns only the **last** match of each type if multiple exist (e.g. unlikely but safe)

### 2. `farmprices/blueprints/admin.py` — Hook into add/edit/import

**`add_product()` (~line 213):** After parsing weight_kg and volume_litres from the form, if both are None, call `parse_weight_volume(name)`:
```python
if weight_kg is None and volume_litres is None:
    weight_kg, volume_litres = parse_weight_volume(name)
```

**`edit_product()` (~line 335):** Same logic — only auto-fill if the user left both fields blank in the form:
```python
if weight_kg is None and volume_litres is None:
    weight_kg, volume_litres = parse_weight_volume(name)
```

**`import_csv()` (~line 683):** After inserting a product via CSV import (which currently doesn't handle weight/volume columns at all), parse from the product name and update:
```python
# After the INSERT, parse weight/volume from name and update
wt, vol = parse_weight_volume(name)
if wt is not None or vol is not None:
    db.execute("UPDATE products SET weight_kg=?, volume_litres=? WHERE id=?",
               (wt, vol, cursor.lastrowid))
```

### 3. `farmprices/db.py` — Add startup backfill in `init_db()`

Add a backfill step at the end of `init_db()` (after existing migrations, before `db.commit()`):

```python
# ── Backfill: extract weight/volume from product names ────────────────
_backfill_weight_volume(db)
```

A helper function `_backfill_weight_volume(db)`:
- Queries: `SELECT id, name FROM products WHERE active=1 AND weight_kg IS NULL AND volume_litres IS NULL`
- For each row, calls `parse_weight_volume(name)`
- If either value is found, updates the product row
- Prints count of updated products (for startup log visibility)

This is **idempotent** — it only touches products where BOTH fields are NULL, so it's safe to run on every startup. As the user fills in values or as new products get auto-populated, fewer rows will need updating.

### 4. `farmprices/helpers.py` — Update `product_snapshot()` to include weight/volume

Currently `product_snapshot()` does NOT include `weight_kg` or `volume_litres` in the audit snapshot. Add them for complete audit trails:

```python
def product_snapshot(p) -> dict:
    return {
        ...existing fields...,
        "weight_kg":         p["weight_kg"],
        "volume_litres":     p["volume_litres"],
    }
```

## Behaviour

- **New products** (add/edit/import): If user leaves weight and volume fields blank, they are auto-extracted from the product name. If the user fills in either field, the auto-extraction is skipped entirely.
- **Existing products**: On each app startup, any active product with both `weight_kg IS NULL AND volume_litres IS NULL` gets its name parsed. This catches products entered before this feature existed.
- **Truly silent**: No flash messages, no UI changes. The fields are populated behind the scenes.
- **Non-destructive**: Never overwrites a value the user has explicitly set.

## Known Limitations

- Container capacity items like "Wheelbarrow 90L" or "Galvanised Bucket 12L" will get `volume_litres` set. These can be manually cleared by the admin if they shouldn't have unit pricing on labels. This is an acceptable trade-off vs. missing genuine litre products.
- Products with both weight AND volume in the name (unlikely in practice) will get both fields set from the name.
